# AI活用度 検査成績書(講演用診断アプリ)

若手経営者向け講演のクロージングで使う診断アプリ。QRコードから来場者のスマホで開き、5問30秒でAI活用度を採点、レベル判定と「次の一歩」を提示する。

- 単一ファイル(`index.html`)。ビルド不要、依存なし(Google Fontsのみ)
- GitHub Pagesでそのまま公開できる

## セットアップ(講演前に済ませる)

1. GitHubにリポジトリ作成(public)、この2ファイルをpush
2. Settings → Pages → Branch: `main` / root で公開
3. 公開URLのQRコードを生成し、最終スライドに貼る
4. **前日と当日朝、会場想定の回線(スマホのテザリング)で必ず表示確認**

## ライブデモの段取り(推奨:二段構え)

### 原則
- **QRは最初から生きている状態にする**(Ver0デプロイ済み)
- ライブでやるのは「Claude Codeに要件を投げて、機能が増えてリリースされる」の実演
- 万一デモが失敗しても、QR先には動くVer0がある=失敗モードは「変化が反映されない」だけ

### タイムライン案
| 講演の位置 | やること |
|---|---|
| §4(自作)の冒頭 | Claude Codeに要件定義を投げる画面を見せ、実行開始。「話している間に作らせておきます」 |
| §4〜§6 | バックグラウンドでCC作業→PR作成(講演は通常進行) |
| §6 結論の直前 | PRをその場でマージ。「今、リリースされました」 |
| 最後 | QR提示。「みなさんのスマホに、たった今できたものが届いています」 |

マージ→GitHub Pages反映は1〜3分かかるため、**マージは結論の3分前まで**に。

### 会場で投げる要件定義(例)
小さく・目に見えて・失敗しにくいものにする。候補:

> 診断結果画面に「社長からの一言」欄を追加してください。レベルごとに違うコメントを表示します。チャット期:「一年前の私もここでした」/手足期:「私の最初の仕事はファイル整理でした」/接続期:「ここを越えると景色が変わります」/自作期:「サウナアプリ、待ってます」/環境設計期:「今度は御社の話を聞かせてください」。既存のデザイン(検査成績書の様式)に合わせてください。

他の候補:
- 6問目を追加(配点調整込み)
- 結果画面にX(旧Twitter)シェア文言のコピーボタンを追加

避けるべき要件:リアルタイム集計・ランキング(バックエンドが必要になり5分では危険)

## リハーサル必須項目
- [ ] CCへの要件投入→PR作成までの所要時間を実測(2回)
- [ ] マージ→Pages反映の所要時間を実測
- [ ] 会場のスクリーンでCC画面の文字が読めるか(フォントサイズ)
- [ ] QR読み取り→初回表示の速度(モバイル回線で)
- [ ] デモ失敗時の逃げ口上を一言決めておく(例:「AIも部下と同じで、たまに納期に遅れます。反映されたら乾杯のときに見てください」)

## 文言の編集箇所
`index.html` 内の `QUESTIONS`(設問と配点)と `LEVELS`(レベル名・評・次の一歩)を編集。
検査者名・様式番号はフッター/ヘッダーのHTMLを直接編集。
